# IPC & Contracts Conventions

**Status:** Draft v1
**Date:** 2026-02-19
**Scope:** Naming, type, and protocol conventions for all IPC contracts

---

## 1) Command Naming

**Convention:** `snake_case` with namespace prefix.

Commands follow Tauri's convention of Rust function names exposed via `#[tauri::command]`.

### Namespaces

| Prefix | Scope | Examples |
|--------|-------|---------|
| `vault_` | Filesystem operations (read, write, watch, move, delete) | `vault_create_page`, `vault_read`, `vault_write`, `vault_delete`, `vault_move`, `vault_list`, `vault_pick_root` |
| `collection_` | Collection definitions and queries | `collection_query`, `collection_query_count`, `collections_list`, `collections_get` |
| `view_` | View definitions | `views_list`, `views_create`, `views_update` |
| `page_` | Page property operations | `page_get`, `page_update_props`, `page_add_tag`, `page_remove_tag`, `page_link`, `page_unlink` |
| `search_` | Search operations (FTS, vector, graph) | `search_global`, `search_semantic`, `search_graph_neighbors` |
| `ai_` | AI/LLM operations | `ai_chat`, `ai_summarize`, `ai_suggest_links`, `ai_rag_query`, `ai_help` |
| `settings_` | Application settings | `settings_get`, `settings_update`, `settings_get_editor_extensions`, `settings_toggle_extension` |

### Phase 0 Bridge Commands

The frontend's `dataService.ts` currently uses domain-specific function names (e.g., `addTask`, `getCalendarEvents`). The contracts wiring matrix (`002_IPC_WIRING_MATRIX.md`) documents these as bridge commands with dot-notation (e.g., `tasks.create`). During Phase 1 IPC wiring, these map to the page-centric commands above:

- `tasks.create` → `vault_create_page(kind: "task", ...)`
- `tasks.list` → `tasks_list_view(cursor?, limit?, scope?, order?)` for migrated hot surfaces; generic `collection_query(collection_id: "col_tasks", ...)` remains available for non-hot-surface / legacy consumers

See `001_architecture.md` Section 6.2 for the full target-state command surface.

## 2) Identifier Format

All entity IDs use UUID v7 (time-sortable) with a type prefix:

| Entity | Prefix | Example |
|--------|--------|---------|
| Page | `pg_` | `pg_01JF8K3M5N7P9Q2R4S6T8V0W` |
| Collection | `col_` | `col_tasks` |
| View | `view_` | `view_tasks_board` |
| Revision | `rev_` | `rev_01JF8K...` |
| Chunk | `chk_` | `chk_01JF8K...` |

**Why prefixed:** Prefixes make IDs self-describing in logs, URLs, and debugging. They prevent accidental cross-type lookups (passing a view ID where a page ID is expected).

**Generation:** UUIDs are generated by the backend only. The frontend never generates IDs — it sends create requests and receives IDs in responses.

## 3) Error Envelope

All error responses use a consistent envelope:

```typescript
interface ErrorResponse {
  error_code: string;     // Machine-readable: "PAGE_NOT_FOUND", "VALIDATION_ERROR", "DB_ERROR"
  message: string;        // Human-readable description
  details?: any;          // Optional structured data (field validation errors, etc.)
}
```

### Error Code Conventions

- `NOT_FOUND` — entity does not exist
- `VALIDATION_ERROR` — request payload failed validation (details contains field-level errors)
- `CONFLICT` — operation conflicts with current state (e.g., concurrent modification)
- `DB_ERROR` — internal database error (details sanitized — no raw SQL)
- `AI_ERROR` — LLM provider error (includes provider name)
- `VAULT_ERROR` — filesystem operation failed
- `ENCRYPTION_ERROR` — SQLCipher or key derivation failure

## 4) Pagination

**Convention:** Cursor-based pagination using opaque backend-issued cursors for generated view transports and stable page-id-derived cursors only for older generic collection helpers that still expose them.

```typescript
interface PaginatedRequest {
  limit?: number;          // Default: 50, Max: 500
  cursor?: string;         // page_id of last result from previous page
}

interface PaginatedResponse<T> {
  items: T[];
  next_cursor?: string;    // null/absent = no more results
  total_count?: number;    // Optional, included when cheap to compute
}
```

**Why cursor, not offset:** Offset-based pagination breaks when items are inserted/deleted between pages. Cursor-based pagination is stable and efficient with SQLite indexes.

**Exception:** `collection_query()` uses cursor pagination by default. Small result sets (< 100 items) may omit pagination entirely. Migrated hot surfaces should prefer the generated `ViewPage<T>` transport family (`tasks_list_view`, `projects_list_view`, `notes_tree_view`, `calendar_occurrences`, `search_query`) with opaque `nextCursor` and `snapshotToken`.

## 5) Date & Time Format

| Type | Format | Example | Storage |
|------|--------|---------|---------|
| Date (no time) | ISO 8601 date | `2026-02-19` | `value_date` in EAV |
| Datetime | ISO 8601 with timezone | `2026-02-19T09:00:00Z` | `value_date` in EAV |
| Time-only | HH:mm (24-hour) | `09:00` | `value_text` in EAV |
| Duration | Minutes (integer) | `90` | `value_num` in EAV |

**Timezone rule:** All datetimes stored in UTC. Frontend converts to local timezone for display. The user's timezone preference is stored in `settings`.

**Range window rule:** Commands that accept date windows (for example `calendar_get_range`) use **inclusive start / exclusive end** semantics: `[start, end)`.

## 6) Null vs. Absent

| Scenario | Representation | Meaning |
|----------|---------------|---------|
| Field not provided in update request | Key absent from JSON | "Don't change this field" |
| Field explicitly cleared | `"field": null` | "Remove this value" |
| Field has a value | `"field": "value"` | "Set to this value" |

This three-state model allows partial updates without requiring the client to send the full entity.

## 7) Property Types in IPC

When sending properties over IPC (e.g., in `vault_create_page` or `page_update_props`), use the following JSON representations:

| Property Type | JSON Type | Example |
|--------------|-----------|---------|
| `text` | string | `"Tokyo"` |
| `number` | number | `3500` |
| `date` | string (ISO date) | `"2026-03-01"` |
| `datetime` | string (ISO datetime) | `"2026-02-20T09:00:00Z"` |
| `select` | string | `"TODO"` |
| `multi_select` | string[] | `["backend", "architecture"]` |
| `boolean` | boolean | `true` |
| `relation` | string (page_id or path) | `"pg_01JFD1..."` or `"/Projects/X.md"` |
| `url` | string | `"https://..."` |
| `currency` | number + companion `currency` field | `150.00` with `"currency": "USD"` |
| `location` | string (lat,lng) | `"40.71,-74.00"` |
| `location_name` | string | `"New York City"` |

## 8) Streaming

For streaming responses (AI chat, long-running operations), use Tauri's event system:

```
// Request
invoke("ai_chat", { model_id, history, context })
// Returns: { request_id: string }

// Stream events
listen("ai_stream_chunk", { request_id, text })
listen("ai_stream_done", { request_id, usage: TokenUsage })
listen("ai_stream_error", { request_id, error: ErrorResponse })
```

The frontend receives a `request_id` immediately and listens for events. This avoids blocking the IPC channel during long-running AI operations.

## 9) Secret Field Conventions (Phase 4)

Secrets are never returned in plaintext over IPC.

- `settings_get` returns masked placeholders (`"********"`) when a secret exists.
- `settings_update` accepts new plaintext secrets for rotation, but should treat unchanged placeholders as no-op.
- Dedicated secret transport commands:
  - `secret_set(request: { secret_key, plaintext }) -> boolean`
  - `secret_get(secret_key) -> string | null`
  - `secret_delete(secret_key) -> boolean`

Transport rule: clients must avoid writing raw secret values to logs and analytics payloads.

## 10) Save-Commit + Indexing Semantics (Phase 4)

Persistence and indexing are explicitly commit-driven.

- `save_commit(request: { page_id, body }) -> Page`
  - returns only after durable write ACK
  - enqueues indexing only after persistence
- `index_queue_status(limit?) -> IndexQueueJob[]`
  - observable queue surface for UI progress/debugging
- unchanged content hash should create `skipped` status with reason `unchanged_hash`
- rapid consecutive saves should coalesce queued jobs by `page_id`

## 11) Voice Provider Settings (Phase 5)

- `AISettings.sttProvider`: `local_whisper | openai | gemini` (current default: `gemini`; local Whisper deferred)
- `AISettings.ttsProvider`: `gemini | openai | local` (default: `gemini`)
- `AISettings.preferredVoice` is provider-specific and must not be constrained to Gemini-only names.
- `ai_transcribe` and `ai_synthesize` select transport behavior from these settings unless an explicit request override is introduced in a future contract revision.

---

## 12) Embedding Provider Settings (ADR-0019)

- `AISettings.embeddingProvider`: `same_as_model | openai | gemini | ollama | hash`
- default: `same_as_model`
- `same_as_model` resolves to the active model provider family when embeddings are available.
- if resolved provider embeddings are unavailable, retrieval falls back to `hash` and status is surfaced in diagnostics/progress.
